# Universal Experience Extraction Protocol v0.1 candidate

## Назначение

Извлечь из истории старого экземпляра не только события, но причинность и изменение будущего поведения.

## Источник

Основной источник — доступная история именно извлекаемого экземпляра и связанные с ней проверяемые артефакты.

Запрещено:
- достраивать пробелы памятью других чатов;
- выдавать historical state за current truth;
- объявлять extracted lesson каноном без отдельного решения;
- скрывать `unknown`.

## Структура эпизода

Для каждого существенного эпизода:

1. задача;
2. контекст/объект;
3. исходная модель/ожидание;
4. evidence/наблюдение;
5. предпринятые действия;
6. неудачные/недостаточные заходы;
7. рабочее решение;
8. проверка результата;
9. изменение модели;
10. lesson;
11. `next_time_behavior`;
12. `prohibited_repeat`;
13. applicability boundary;
14. freshness/status;
15. evidence refs.

## Плантация граблей

Для каждой отдельной ловушки:
- симптом;
- причина или `unknown`;
- почему прежняя проверка её не поймала;
- как обнаружили;
- что делали зря;
- правильный подход;
- `next_time_behavior`;
- `prohibited_repeat`;
- candidate anti-regression test;
- evidence.

Не объединять разные причины ради краткости.

## Reusable procedures

Выделять будущие runbook/checklist только из реально подтверждённых эпизодов. Для каждой процедуры указывать исходные эпизоды и границы применимости.

## Незавершённое состояние

Отдельно перечислить `open / parked / blocked / unknown / superseded` как historical extraction. Не превращать это автоматически в current tasks.

## EXTRACTION_REPORT

Обязательно указать:
- фактически доступный диапазон истории;
- виден ли чат от начала;
- недоступные участки;
- количество эпизодов;
- количество граблей;
- количество reusable procedures;
- количество experience cards;
- количество anti-regression candidates;
- количество unknown;
- направления, которые могли остаться вне контекста.
